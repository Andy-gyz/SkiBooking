# Snow Alpine production runbook

Milestone 16 prepares the application for deployment without creating paid
cloud resources. Milestone 17 will execute this runbook.

## Portfolio target architecture

```text
Customer browser
  ├─ snowalpineresort.com ──> Vercel / Next.js
  └─ api.snowalpineresort.com ──> Caddy HTTPS / Lightsail
                                      ├─ Spring Boot container
                                      └─ PostgreSQL container + persistent volume

Stripe webhooks ──> api.snowalpineresort.com/api/payments/webhook
Resend ──> verification email from bookings@mail.snowalpineresort.com
```

The portfolio deployment intentionally uses one 2 GB Lightsail instance to
avoid the standing cost of App Runner, RDS, and a NAT gateway. PostgreSQL is
not exposed to the internet; only Caddy publishes ports 80 and 443. This is a
cost-conscious portfolio topology, not a high-availability commercial setup.
The executable files live in [`deploy/lightsail`](../../deploy/lightsail/).

## Production domains

| Purpose | Domain |
| --- | --- |
| Canonical customer site | `snowalpineresort.com` |
| Optional redirect | `www.snowalpineresort.com` → `snowalpineresort.com` |
| Backend API | `api.snowalpineresort.com` |
| Resend sending domain | `mail.snowalpineresort.com` |

Do not copy guessed DNS values from this document. Vercel, App Runner and
Resend each generate account-specific DNS records. Add exactly the records
shown in their dashboards at the DNS provider that owns the authoritative name
servers.

Resend recommends a subdomain to isolate sending reputation. Add
`mail.snowalpineresort.com` in Resend, copy its SPF, DKIM and MX records into
DNS, wait for `Verified`, and then use
`Snow Alpine <bookings@mail.snowalpineresort.com>` as `EMAIL_FROM`. See
[Resend domain verification](https://resend.com/docs/dashboard/domains/introduction).

## Backend production variables

Store secret values only in the root-readable `deploy/lightsail/.env` file on
the server. Never commit the production file; the repository contains only an
example.

| Variable | Production value or source |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | `production` |
| `DB_URL` | Internal Compose URL `jdbc:postgresql://postgres:5432/skibooking` |
| `DB_USERNAME` | Server `.env` |
| `DB_PASSWORD` | Server `.env` |
| `JWT_SECRET` | At least 48 random bytes, server `.env` |
| `JWT_ISSUER` | `snowalpine-api` |
| `CORS_ALLOWED_ORIGINS` | `https://snowalpineresort.com,https://www.snowalpineresort.com` |
| `STRIPE_SECRET_KEY` | Stripe test secret initially; live key only at launch |
| `STRIPE_WEBHOOK_SECRET` | Secret generated by the production webhook endpoint |
| `RESEND_API_KEY` | Restricted Resend production API key |
| `EMAIL_FROM` | `Snow Alpine <bookings@mail.snowalpineresort.com>` |
| `INITIAL_ADMIN_EMAIL` | Private administrator mailbox |
| `INITIAL_ADMIN_PASSWORD` | Unique 12+ character bootstrap password |

The production profile fails during startup if a required value is missing,
still contains a placeholder, enables localhost CORS, or uses an unverified
sender domain. RDS PostgreSQL supports encrypted SSL/TLS connections; AWS
documents certificate verification options in its
[RDS PostgreSQL SSL guide](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/PostgreSQL.Concepts.General.SSL.html).

The initial administrator is created only when the email does not exist. Its
password is not reset during later restarts. After the first successful login,
rotate the bootstrap secret in AWS and retain the resulting account.

## Frontend production variables

Configure these in Vercel for both Preview and Production, then redeploy after
any change because `NEXT_PUBLIC_` values are embedded at build time.

| Variable | Production value |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://snowalpineresort.com` |
| `NEXT_PUBLIC_API_BASE_URL` | `https://api.snowalpineresort.com` |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Matching Stripe test/live publishable key |
| `API_BASE_URL` | `https://api.snowalpineresort.com` |

Vercel supports separate Preview and Production variables. See the official
[Vercel environment variable guide](https://vercel.com/docs/environment-variables).

## Stripe endpoint

Create a Stripe webhook endpoint at:

```text
https://api.snowalpineresort.com/api/payments/webhook
```

Subscribe only to:

```text
payment_intent.processing
payment_intent.succeeded
payment_intent.payment_failed
payment_intent.canceled
```

Copy the endpoint's own `whsec_...` secret to the server `.env`. The local
Stripe CLI webhook secret cannot be reused in production.

## Deployment gates

Before public launch, every item must pass:

- GitHub CI passes backend tests, frontend lint and frontend production build.
- All three Lightsail containers report healthy/running.
- PostgreSQL 17 is reachable only on the private Compose network.
- An encrypted PostgreSQL dump is stored outside the instance before updates.
- `https://api.snowalpineresort.com/actuator/health` returns `UP` without details.
- Browser CORS succeeds only from the customer domains.
- Resend domain is verified and a real verification email arrives.
- Stripe test checkout and signed webhook confirmation complete end to end.
- An administrator generates future lesson sessions before lessons are sold.
- Customer, payment and admin routes are excluded from `robots.txt`.
- Both domains have valid HTTPS certificates.

Caddy automatically provisions and renews the API TLS certificate after the
DNS A record resolves and ports 80 and 443 are reachable.

## Image hosting decision

Product photography is currently bundled with the Next.js application and
served by Vercel's image pipeline. This is reliable for the fixed MVP catalog
and avoids introducing an S3 upload workflow before administrators can manage
files. Moving administrator-uploaded media to S3 is deferred until that upload
feature is implemented; externally pasted image URLs remain supported by the
catalog API.
